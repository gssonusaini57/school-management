iOS project at `ios/` uses **XcodeGen** — `project.yml` is the single source of truth. The `.xcodeproj` is gitignored and regenerated by running `xcodegen` inside `ios/`.

**Why:** `.pbxproj` is a UUID-laden text format that produces awful merge conflicts and frequently corrupts when edited by anything other than Xcode itself. XcodeGen lets us version-control a clean YAML config like Android does with `build.gradle.kts`. User chose this over committing the Xcode project directly when scaffolding the iOS app in Session 7.

**How to apply:**
- When adding new Swift files: just drop them under `ios/KisAttendance/`. XcodeGen's `sources: - path: KisAttendance` rule auto-includes everything; no manual project edits needed.
- When adding a new dependency or build setting: edit `ios/project.yml`, then re-run `xcodegen` (the build script does this automatically).
- Do NOT add `KisAttendance.xcodeproj/` to git — it's gitignored on purpose.
- Build/distribution flow is `cd ios && xcodegen && ./scripts/build-ios.sh` (or open the regenerated project in Xcode for dev work).
- Version bumps: edit `MARKETING_VERSION` in `ios/version.xcconfig` for user-visible changes; `CURRENT_PROJECT_VERSION` (build #) is auto-incremented by `build-ios.sh`. Mirrors how `android/version.properties` works.
