Session 15 (2026-06-06, shipped in APK v1.2.3 / build 16, prod). Android teacher app gained:

- **Back-dated attendance**: `AttendanceScreen` date is now a `DateField` picker capped at today (`maxIso = todayIso()`); the backend `PUT /attendance` already accepted any date. `DateField` (ui/components/CommonComponents.kt) gained optional `minIso/maxIso` via Material3 `SelectableDates` (UTC-millis, reuses `parseIso`).
- **Coverage dashboard** = the new home landing (`HomeScreen` now takes a `DashboardViewModel`): per-class **month calendar** (`ui/screens/dashboard/MonthCalendar.kt`) — green=marked, amber=missed (past **Mon–Sat** working day, no record), grey=off(Sunday)/future, today ringed. Tap a past day → opens Attendance pre-set to that (class, date) via `Routes.attendanceFor(c, iso)` (parameterized `attendance?class=&date=` route; `AttendanceViewModel` takes optional `initialClass/initialDate`). After save, an `attendance_changed` savedStateHandle flag makes the dashboard `reloadCurrentMonth()` (same pattern as `student_edited`/`students_changed`).
- **Working-week policy** is ONE knob: `WORKING_WEEK` in `ui/screens/dashboard/WorkingWeek.kt` (currently `MON_SAT`). Holidays can't be auto-detected → a holiday shows as "missed" (informational only).
- **New backend endpoint**: `GET /attendance/marked-dates?class=&from=&to=` (staff-scoped via `assert_class_allowed`) → `{dates:[ISO,…]}` (distinct attendance dates in range). Schema `MarkedDatesOut`. One request per month vs one GET/day.
- Date math in the dashboard uses `java.time.LocalDate`/`YearMonth` (native on minSdk 26), kept separate from the UTC-millis picker path. See [[project_android_force_update]].

Also (v1.2.3): app renamed **"KIS Attendance" → "KIS School Portal"**; launcher icon is now the **KIS crest** (white bg) generated by `scripts/gen_android_icon.py` from `crest-full.png`; pending-edit lock fix — detail/edit screens fetch `GET /students/{id}` (staff CAN call it; the old "admins only" comment was wrong) so the "pending approval" banner + Edit-disable work. See [[feedback_notify_never_raises]].

**v1.2.4 / build 17 (2026-06-06):** (a) **Half-day "H"** per-student status + **day-level Holiday** + **"Clear day"** correction. Migration **0012** widens the native MySQL `attendance_records.status` ENUM to add `H` (raw `ALTER TABLE ... MODIFY ... ENUM('P','A','L','H')`; downgrade remaps H→A first) and adds `attendance.is_holiday`. `PUT /attendance` takes `is_holiday` (stores no records when true) + accepts `H`; new `DELETE /attendance?class=&date=` clears a day; `/attendance/marked-dates` now returns `{dates, holidays}` and the calendar shows Holiday distinct (never "missed"). (b) **In-app approval portal** (super-admin only — all `/admin/*` list endpoints are super-admin-gated, matching the web): `ApprovalsScreen` (FilterChip tabs) reviews student-edit diffs, marks edits, deletions (approve/restore/purge) via existing `/admin/edit-requests`, `/admin/marks-edit-requests`, `/admin/deletion-requests`. App is now **role-aware**: `TokenStore`/`AuthRepository` persist+expose `role` (login/me already returned it); HOME fires `refreshMe()` so old installs hydrate role without re-login. Approvals tile shows only when `isSuperAdmin`.
